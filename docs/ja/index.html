ここに書かれていることはすべて実際に動作する。AXIS Q1656 実機1台、Base Sepolia テストネット上で。 主張はそれだけであり、それ以上ではない。これはラボ用ビルドである： 未署名, テストネット限定, カメラ1台。本番導入なし、パイロット顧客なし、メインネットの資金なし。目的は「AXIS カメラは x402 の売り手になれるか」に答えることであって、購入されること、フリートに導入されること、インターネットに公開されることではない。上の内容から結論を出す前に、ページ末尾の状況の注記を読んでほしい。

CamWallet は、登録済みの AXIS カメラを x402 の売り手に変える ACAP である。エージェントはリクエストごとに支払い、範囲を絞った、プライバシーを最小化した、監査可能な答えを1つ受け取る。

実機で動作中：CamWallet 0.8.2、AXIS Q1656、Base Sepolia
命題
AXIS カメラに価格表と、ポリシーエンジンと、安全な経済的インターフェースを与える。

商品は「署名された運用上の証拠」である。x402 はプログラムから使える決済レールにすぎない — ありふれたレジ台であって、顧客への価値提案ではない。

有料の単位

A 価格の付いたリソース は、設定された1つの問いに答える。来歴と、ポリシーと、監査証跡を伴って。

実際の例： 見知らぬウォレットが、0.002 USDC でカメラから 44 KB の JPEG を購入した。あるいはフィールド抽出を使えば、返るのは {"value":0,"unit":"buses"} だけ — 買い手は、何人の人が通り過ぎたかを知ることはない。

カメラからエージェントへの能力提供

汎用の映像解析ではない。カメラ映像の公開でもない。「AI エージェントがカメラを操作する」でもない。汎用の x402 クライアントは、このカメラのために特別な処理を書く必要がない — 必要になったなら、それはバグである。

x402 の流れ
01 / リクエストエージェントが尋ねる所有者がカタログに公開したパスを叩く。既定は拒否、完全一致、ワイルドカードなし。
02 / チャレンジACAP が 402 を返す標準のボディ：ルールごとの価格、資産、チェーン、payTo。
03 / 承認エージェントが支払う署名済みの PAYMENT-SIGNATURE ヘッダーを付けて再送する（v2。 X-PAYMENT も引き続き受理）。カメラは鍵を持たない。
04 / 検証ファシリテーターが決済する/verify のあとに /settle。リース、クールダウン、レート制限は capture の前に確認される。
05 / 引き渡しカメラが応答するauthorize → produce → capture。何も渡せなければ、何も課金されない。

堅いガードレール（検証済み）
  • カメラに鍵を置かない — 受取アドレスは管理者が貼り付ける
  • 上書き不可の拒否リスト：危険なパス 10/10 を拒否
  • 買い手のパス ≠ カメラ側のターゲット。カタログはターゲットを公開しない
  • extract は1つのフィールドだけを売る。ペイロード全体ではない
  • フェイルクローズ：ファシリテーターに到達できなければ 402。何も渡さず、何も課金しない
  • 管理インターフェースはループバック限定 — 設定、受取先、価格表がネットワークに出ることはない
  • ファシリテーターと RPC への接続は TLS を検証する。証明書の例外は端末内のホップだけに限定されている
  • 再送された支払いが二重に課金されることはなく、新しい答えを生むこともない
  • キルスイッチ：解除＋リース終了＋復帰をワンクリックで
対象外／未解決
  • アクセス制御ではない — 認証情報を持つ利用者は常に VAPIX と RTSP に直接到達できる
  • インターネット公開はまだ：Axis Device ID の証明書は公的に信頼されていない
  • メインネットなし — Base Sepolia のみ
  • クォータパックなし（ kind フィールドが将来の接ぎ目）
  • 法的・法科学的な証拠能力の主張はしない
  • 決済失敗：直近18回の購入で0件。ただし 再現しない は「修正済み」ではない

価格はルールごと、USDC の最小単位で指定する — 1000 = 0.001 USDC。目安：開発者向けは1回あたり €0.02–€0.20、業種別の運用パックは1サイトあたり月額 €99–€499。

アーキテクチャ決定（ADR-002）

エッジ優先、鍵を持たない、可能な限り標準どおり。

402 の扉は ACAP 自身であり、カメラ自身の Web サーバー上で reverseProxy を通じて匿名で提供される — 追加のポートも、追加の TLS も要らない。/verify と /settle は第三者のファシリテーターが行い、ACAP は決済スタックを実装しない。カメラ固有の意味づけ（リース、能力の記述）はリソース層にあり、決済の内側には決して置かない。

実際の到達点
P0–P2 / レールの実証

匿名プロキシからアプリへの到達、管理者が入力する受取先、チェーンへの到達性、6 ms の時刻差。Base Sepolia 上で初の実決済 — カメラが何かを売り、代金を受け取った。

P3–P4 / 製品

所有者の価格表、ライブ探索、プライバシー制御としてのフィールド抽出、副作用の明示。自動復帰つき PTZ 排他リース、409 による排他制御とクールダウンを、資金のある2つのウォレットで検証。

P5 / 運用可能

カメラごとの売上台帳を兼ねる監査ログ、キルスイッチ、CSV エクスポート、OPERATOR.md。到達不能なファシリテーターに対してフェイルクローズを実地に確認。

所有者が実際に目にする画面

製品の全体は、カメラ上の設定ページ1枚である。カメラ自身の Web サーバーが、管理者ログインの内側で提供する。スクリーンショットはラボの Q1656 上の CamWallet 0.8.2（画面は英語）。受取アドレスと USDC のコントラクトはマスクしてある。

次の一手

実在の買い手に耐える 堅さを作り、それからメインネットへ。

全応答を記録する新しい計測で決済不具合を潰す。リバースプロキシまたはトンネルを使い、公的に信頼される証明書を1台のカメラの前に置く — ログイン画面や VAPIX、RTSP まで一緒にポート開放してしまうことなく。そのうえで、Base メインネットで有償のパイロットを1件。

製品ではなくプロトタイプ： 未署名のラボビルド、Base Sepolia テストネット、カメラ1台、パイロット顧客なし。本ページはソフトウェアの販売の申し出でも、製品として利用可能であるという主張でもない。

前提となる状況： AXIS Q1656（FW12）上で動作する CamWallet 0.8.2、Base Sepolia テストネット、第三者のファシリテーター。原則：可能な限り x402 標準に沿う — USDC のみ、単一チェーン、v2 の exact スキーム、標準の v2 PAYMENT-SIGNATURE / PAYMENT-RESPONSE / PAYMENT-REQUIRED （v1 の表記も引き続き読み取り・送出する）。本番導入の前に、ライブラリのバージョン、機種とファームウェアの対応、受取先の資産管理、EU のプライバシー義務を各自で確認すること。

x402 × AXIS Camera Application Platform

CamWallet is an ACAP that turns an enrolled AXIS camera into an x402 seller: an agent pays per request and receives one narrow, privacy-minimized, audited answer.

Running on hardware: CamWallet 0.8.2, AXIS Q1656, Base Sepolia
The thesis
Give an AXIS camera a price list, a policy engine and a safe economic interface.

The product is signed operational evidence. x402 is the programmatic payment rail — a commodity checkout counter, not the customer value proposition.

The paid unit

A priced resource answers one configured question, with provenance, policy and an audit trail.

Shipped example: a stranger's wallet bought a 44 KB JPEG from the camera for 0.002 USDC. Or, with field extraction, only {"value":0,"unit":"buses"} — the buyer never learns how many people walked past.

Why this is distinct

Camera-to-agent capability

Not generic video analytics. Not an exposed camera stream. Not “an AI agent controls cameras.” A generic x402 client needs no special case for the camera — if it does, that's a bug.

How the x402 flow works
01 / REQUESTAgent asksHits a path the owner published in the catalog. Default deny, exact match, no globs.
02 / CHALLENGEACAP returns 402Standard body: price per rule, asset, chain, payTo.
03 / AUTHORIZEAgent paysRetries with a signed PAYMENT-SIGNATURE header (v2; X-PAYMENT still accepted). The camera holds no key.
04 / VERIFYFacilitator settles/verify then /settle. Lease, cooldown and rate limits checked before capture.
05 / DELIVERCamera respondsauthorize → produce → capture. Nothing charged if nothing delivered.
Capabilities working today
  • Snapshot / redacted still, priced per call
  • AOA per-class counts, one number per rule
  • CamSwitcher view + CamStreamer stream control
  • Exclusive PTZ preset leases with auto-revert

Hard guardrails (verified)
  • No key on the camera — payee address is pasted in by the admin
  • Non-overridable denylist: 10/10 dangerous paths refused
  • Buyer path ≠ camera target; the catalog never publishes the target
  • extract sells one field, not the payload
  • Fail-closed: facilitator unreachable → 402, nothing served, nothing charged
  • Admin surface is loopback-only — settings, payee and price list are never on the network
  • Facilitator and RPC connections verify TLS; the certificate exception is scoped to the in-device hop
  • A replayed payment is never charged twice and never produces a fresh answer
  • Kill switch: disarm + release lease + revert, one click
Not in scope / open
  • Not access control — credentialed users always reach VAPIX and RTSP directly
  • No public exposure yet: Axis Device ID cert isn't publicly trusted
  • No mainnet — Base Sepolia only
  • No quota packs (the kind field is the seam)
  • No legal / forensic admissibility claims
  • Settle failures: 0 in the last 18 buys, but not reproducible ≠ fixed

Architecture decision (ADR-002)

Edge-first, keyless, maximally standard.

The 402 door is the ACAP itself, served anonymously on the camera's own web server via reverseProxy — no extra port, no extra TLS. A third-party facilitator does /verify and /settle; the ACAP implements no payment stack. Camera-specific semantics (leases, capability descriptions) live in the resource layer, never inside the payment.

Where the build actually stands
P0–P2 / Rail proven

Anonymous proxy reaching the app, admin-supplied payee, chain reachability and a 6 ms clock. First real settlement on Base Sepolia — a camera sold something and got paid.

P3–P4 / Product

Owner price list, live discovery, field extraction as a privacy control, side-effect flagging. Exclusive PTZ leases with auto-revert, 409 exclusivity and cooldown, verified with two funded wallets.

P5 / Operable

Audit log that doubles as the per-camera revenue ledger, kill switch, CSV export, OPERATOR.md. Fail-closed exercised against an unroutable facilitator.

What the owner actually sees

The whole product is one settings page on the camera, served through the camera’s own web server and behind its admin login. Screenshots are from CamWallet 0.8.2 on the lab Q1656; the payee address and USDC contract are masked.

Next move

Harden for a real buyer, then mainnet.

Close the settle defect with the new full-response instrumentation. Put a publicly trusted cert in front of one camera via reverse proxy or tunnel — without port-forwarding the login page, VAPIX and RTSP with it. Then one paying pilot on Base mainnet.

Validate library versions, device/firmware support, payee custody and EU privacy obligations before production.
